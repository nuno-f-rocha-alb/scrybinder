# Building and developing Scrybinder

## Requirements

- Python 3.12 and [uv](https://docs.astral.sh/uv/)
- Node.js 20+ (for the UI)
- [Tesseract OCR](https://github.com/tesseract-ocr/tesseract) with the `eng` language data, on `PATH` (or set `SCRYBINDER_TESSERACT`)

## Setup

```bash
uv sync --extra vision          # CPU PyTorch (visual identification)
# or: uv sync --extra vision-cuda   # NVIDIA GPU build (Windows/Linux, cu128)
# or: uv sync                       # no visual identification (OCR only)
cd ui && npm ci && npm run build   # produces ui/dist, served by the backend
```

`uv sync` without an extra removes PyTorch from the environment.
The `vision` and `vision-cuda` extras conflict; pick one.

## Run

```bash
uv run scrybinder              # native window (pywebview)
uv run scrybinder --browser    # open in the default browser instead
uv run scrybinder --serve      # only start the server and print the URL
```

UI development with hot reload: run the backend (`--serve`), then `cd ui && npm run dev`.

## Tests

```bash
uv run pytest
cd ui && npm run build         # type-checks (tsc) and builds
```

Tests use synthetic fixtures generated by `tests/make_fixtures.py`; no personal data or network access is needed.

## Environment variables

| Variable | Purpose |
|---|---|
| `SCRYBINDER_DATA` | Data directory (database, card index, images). Overrides the default location. |
| `SCRYBINDER_TESSERACT` | Path to the `tesseract` executable. |
| `SCRYBINDER_MODEL` | Hugging Face id of the embedding model (default `facebook/dinov2-base`). |
| `SCRYBINDER_AUTO_BULK` | `0` disables the automatic Scryfall bulk-data download. |

Default data directory: `data/` next to the project (or next to the executable if it exists, or `portable.txt` is present);
otherwise `%LOCALAPPDATA%\Scrybinder`, `~/Library/Application Support/Scrybinder` or `~/.local/share/scrybinder`.

## Releases and updates

A release is one command and one merge. Keep `CHANGELOG.md` up to date as you go: put each change under `## [Unreleased]` in the PR that makes it (these entries become the release notes).

1. **Merge what goes into the version** (CI must pass: `main` is protected).
2. **Prepare the release** from an up-to-date `main`:

   ```bash
   uv run python packaging/release.py prepare 0.4.0 --dry-run   # shows the notes and the files that change; changes nothing
   uv run python packaging/release.py prepare 0.4.0             # branch release/0.4.0, version bump, changelog, PR
   ```

   It refuses a version that is not newer, an empty `[Unreleased]`, a dirty tree or an out-of-date `main`. It bumps the version in `pyproject.toml`, `scrybinder/__init__.py` (shown in Settings) and `uv.lock`, moves `[Unreleased]` under the new version with today's date, pushes the branch and opens the PR.
3. **Merge the release PR** when CI is green.
4. **Nothing else.** `.github/workflows/tag-release.yml` sees the version change land on `main`, creates the tag `v0.4.0` and starts `release.yml`, which builds, smoke-tests the packaged app and publishes the installer, the portable zip, `manifest.json`, an update package and `SHA256SUMS`, with the changelog section as the notes. It takes about 20 minutes.

Things worth knowing:

- A version with a hyphen (`0.4.0-rc1`) is published as a pre-release.
- *Actions → Release → Run workflow* does a dry run of the build (publishes nothing). *Actions → Tag release → Run workflow* (dry run on by default) says what the tagging step would do.
- If the automatic tag does not appear, do it by hand from an up-to-date `main`: `git tag v0.4.0 && git push origin v0.4.0` (a tag pushed by a person starts `release.yml` directly).
- The tag workflow starts `release.yml` itself because a tag pushed with the workflow token does not trigger other workflows.

`manifest.json` lists the SHA-256 of every app file (it also ships inside the app folder). The update package is built from the manifest of the previous release (`packaging/make_update.py`); an in-app updater can use the same two files: compare manifests, download the changed files, restart.

## Packaging

Packaging is done by PyInstaller with `packaging/scrybinder.spec`, driven by the GitHub Actions release workflow
(`.github/workflows/release.yml`, triggered by a `v*` tag). To build locally:

```bash
(cd ui && npm ci && npm run build)
UV_PROJECT_ENVIRONMENT=.venv-cpu uv run --extra vision --with pyinstaller pyinstaller packaging/scrybinder.spec --noconfirm
```

On Windows, put a copy of the Tesseract install folder at `packaging/tesseract/` before building (with `tessdata/eng.traineddata`)
and it is bundled; the app finds it automatically. The Windows installer is built with
[Inno Setup](https://jrsoftware.org/isinfo.php) from `packaging/scrybinder.iss`.
Releases are Windows only. CI also builds a Linux bundle (not published) to check that packaging works; macOS is not built.
